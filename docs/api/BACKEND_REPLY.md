## 2. Где бэк отступил от спеки или уточнил её

1. **SSE и авторизация.** `EventSource` не умеет заголовки, поэтому `GET /runs/{id}/events` принимает и `?access_token=<access>` (только этот эндпоинт). Токен проверяется при подключении; по истечении access-токена переподключайтесь с новым. Имя события уровня разбора — `run.progress` (в спеке не было), конечное — `run.done`; после него поток закрывается. `Last-Event-ID` не поддерживается: при переподключении приходит свежий снимок.
2. **`eta_seconds`** бывает `null` только если ни у одного файла нет числа страниц. Пока сервер не накопил скорости, оценка идёт по значениям по умолчанию — первая цифра есть сразу. Сглаживание хранится в памяти сервера: после его перезапуска процент может ненадолго откатиться к оценке по времени (но не ниже прежнего значения внутри одного процесса).
3. **`FAKTURA_PARALLEL`** не заводили: параллельность берётся из самого разбора.
4. **`suggested_domain`** приходит только в полном `files` (`GET /runs/{id}`), не в коротком списке `GET /runs`, и только у `status: "out"`.
5. **Ошибки 422 vs 400.** Случаи из §7а (пустой `file_ids`, та же область и т. п.) — `422 validation_error`, как в спеке. Неверные типы полей в JSON (`pinned: "maybe"`) — общий `400 validation_error`.
6. **Остановленный разбор** получает обычный итоговый `status`: `done`, если хоть один файл готов, `error` — если ни один. Остановленные файлы — `error` с `reason: "остановлено"`, их можно запустить через `restart`.
7. **`restart`** может вернуть результаты из кеша сервера для неизменённых PDF (тот же файл и версия модели).
8. **`POST /runs/{id}/files` в идущий разбор** разрешён: файлы встают в ту же очередь. В завершённый — стартует прогон только по новым файлам.
9. **Правки (v2):**
   - правка, присланная на повтор (`duplicate_of`), применяется к основной записи — это видно в `applied_to`;
   - пересчёт правил после правки может открыть «дополнительные» замечания с id `V…`; они есть в `GET /papers/…`, `/issues/stats` и счётчиках, но не в списке `GET /issues`;
   - в строках таблиц `GET /papers/…` колонки остаются ровно как в шаблоне; состояние правок — в отдельных картах `reviews` и `issue_states`.
10. **«Лучшее значение»** — поле `best_values` в `GET /runs/{id}/summary`, только для `solar` (у `rag` пустой объект). Экран «Сравнение» убран, поэтому поле необязательное: остаётся в сводке, использовать не обязательно.
11. **Паспорт в ZIP** теперь в формате §7а.6 (тот же, что отдаёт `passport.json`); прежний формат из ZIP убран.
12. **Экспорт Excel:** в вашем `toXlsx` (`src/exporters.ts`, `colName`) имена колонок ломаются после 26-й (Z → AA), а в `results` солнечной области 27 колонок. Серверный `dataset.xlsx` это учитывает; локальный экспорт стоит поправить.
13. **Словарь:** материалы на сервере без человеческих названий (подпись — формула), условия — спектры освещения (`AM1.5G` и др.); условия «MPP-tracking» на сервере нет. Повтор написания — `409 synonym_exists`, удаление встроенного — `409 synonym_builtin`. Свои синонимы действуют на новые разборы и перезапуски, старые не пересчитываются.
14. **Вопросы по разбору:** LLM только переводит вопрос в запрос и коротко формулирует текст; значения и ссылки берутся из строк разбора (с учётом правок). До 50 строк в карточке, вопрос до 500 символов (`422`), 30 вопросов в минуту (`429`). Если сервис модели недоступен, ответ строится по ключевым словам — пользователь всё равно получает ответ (`meta.degraded: true`). Поле `meta` в ответе можно не читать. Карточку `compare` сервер не отдаёт.

## 3. Ответы на открытые вопросы (§12)

1. **`/papers/{domain}/{pid}` пока файл в `running`:** `200` с пустыми массивами, `paper_status: "nodata"`, текущий статус файла — в `meta.file_status`. Ваше предложение принято, `409` не отдаём.
2. **`has_data` у `out`:** всегда `false` — строк `results` у статьи не по теме нет.
3. **Refresh-cookie:** httpOnly, `SameSite=Strict`, `Secure` (на сервере), путь — только эндпоинты `/auth`. Срок — 30 дней с «запомнить меня», иначе 12 часов; ротация при каждом `refresh`. При одном домене через прокси это работает без изменений; для разных доменов `Strict` придётся ослабить — скажите, если понадобится.
4. **Multipart и заголовки выгрузки:** поля `file` (повторяемое) и `archive` — подтверждаем. Заголовки ZIP: `X-Export-Filename`, `X-Export-Papers`, `X-Export-Results`, `X-Export-Tables`, `X-Export-Rejected`, `X-Check-Status`; все в `Access-Control-Expose-Headers` вместе с `X-Request-Id` и `X-Action-Id`.
5. **Обмен с сервисом разбора** — внутренний, фронта не касается: синхронный HTTP, ответ потоком NDJSON и запись строк пачками (`docs/design/ML_NDJSON.md`).
