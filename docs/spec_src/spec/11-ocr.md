# 11. OCR — сканы без текстового слоя

[← К оглавлению](../BACKEND_SPEC.md)

> **Для области 2 (RAG) OCR обязателен.** В архиве области 2 около 15 % PDF — синтетические сканы без текстового слоя (растеризация с перекосом, шумом, размытием, сжатием, неравномерным освещением и волной строк): **3 из 21 dev — D002, D013, D021; 14 из 90 test**. Без OCR их значения не извлечь, а это прямые потери по оценке. В области 1 сканов в архиве нет, но конвейер общий — OCR включается автоматически для любой страницы без текста.

## 11.1. Где OCR в конвейере

```
Загрузка [BE] → Проверка текстового слоя по страницам [BE] → OCR страниц без текста [ML-2: Tesseract или аналог]
             → «документ» (текст + слова с bbox и уверенностью) [ML-2] → Извлечение [ML-1] → Нормализация, проверки [BE]
```
OCR делает **ML-2 в `/ml/parse`** — перед извлечением, постранично, только для страниц без извлекаемого текста. ML-1 получает обычный «документ» и не отличает скан от текста, кроме флагов `ocr_used`. Этап в интерфейсе — «Распознавание скана».

Движок: **Tesseract 5** (`eng`; для русскоязычных статей — `eng+rus`), рендер страниц PyMuPDF при 300 dpi (как в `check_submission.py`, `--ocr-dpi 300`); перед распознаванием — выравнивание перекоса, шумоподавление, бинаризация. Допустим другой движок (PaddleOCR, docTR) — контракт тот же. Таблицы на сканах — распознавание структуры таблиц (по линиям или по выравниванию слов), ячейки с bbox.

## 11.2. Как определяется «нет текстового слоя» [BE]

Так же, как это делает `check_submission.py` области 2: страница — **скан**, если текст, извлечённый **pypdf и PyMuPDF**, после нормализации (NFKC, пробелы) пуст на обоих движках. Дополнительно (на случай битых шрифтов): текста < 20 символов при изображении на ≥ 70 % площади, или > 30 % символов `�`/Private Use Area → страница идёт в OCR как дополнительный вариант текста.

Статья — **скан**, если OCR понадобился хотя бы для одной страницы: `Paper.ocr.used = true`, статус файла в разборе — `done` с пометкой «скан, распознано OCR» (статус `ocr` — только если OCR не справился или недоступен).

## 11.3. Поля (уже в контракте)

### От ML-2 (`/ml/parse`, «документ»)
| Где | Поле | Описание |
|---|---|---|
| `pages[]` | `ocr_used` | страница распознана OCR |
| `pages[]` | `ocr_confidence` | средняя уверенность страницы 0…1 |
| `pages[]` | `ocr_language`, `dpi`, `deskew_deg` | |
| `pages[]` | `words` | `[{text, bbox, confidence}]` — текстовый слой для поиска цитат и выделения |
| `tables[].cells[]` | `ocr_confidence` | |
| конверт | `ocr` | `{used, engine, engine_version, pages: [n], mean_confidence}` |

### В модели бэка
| Сущность | Поле | Ист. |
|---|---|---|
| `Paper` | `ocr: {used, pages, mean_confidence, engine}` | [ML]/[BE] |
| `RunFile` | `scan: true`, `ocr_confidence` | [BE] |
| `Fact` / строка `results` (в `meta`) | `ocr_used`, `ocr_confidence` (уверенность распознавания символов значения — отдельно от `confidence` извлечения) | [ML] |

Правило `ocr_low_confidence` [BE]: `ocr_confidence < 0,8` у числового значения → замечание в интерфейсе «Значение со скана распознано неуверенно: сверьте цифры» (в `issues.csv` не выгружается — это не замечание к статье), строка не попадает в «принять надёжные».

## 11.4. Цитаты со сканов

- `source_fragment` пишется **буквально так, как напечатано на странице**, а не как распознал OCR с ошибками: ML-1 берёт текст OCR, но сверяет числа и знаки по контексту; сомнительные символы не «исправляются», а отмечаются в `note`.
- Проверка `check_submission.py --ocr` распознаёт страницу Tesseract-ом и ищет цитату **буквально**; не нашла — «непроверено» (код 2), а не ошибка. Поэтому для сканов предпочтительны **короткие** цитаты (подпись таблицы, заголовок строки, фраза с числом), а для табличных значений — `source_table` и строка/столбец в `note`.
- Бэк ставит `quote_found` по тексту OCR той же нормализацией; для сканов интерфейс показывает «цитата не подтверждена OCR — сверьте по изображению».
- Номера страниц у сканов те же, что у оригиналов (эталон составлен по оригиналам).

## 11.5. Интерфейс

- Файл в разборе — пометка **«скан, распознано OCR»** (и средняя уверенность); в шапке статьи — то же с числом страниц-сканов.
- Просмотр PDF: изображение страницы + невидимый текстовый слой из `words` (поиск цитаты и выделение работают). Подсветка — по `bbox` слова/ячейки (для сканов `bbox` от OCR есть всегда).
- **Низкая уверенность — отдельно**: значение подчёркнуто янтарным пунктиром, в карточке «распознано со скана: уверенность 76 %», фильтр «низкая уверенность OCR» в таблице результатов.
- В выгрузку OCR-признаки не идут (только в `_meta/facts_ui.json`).

## 11.6. Ошибки и деградация
| Код | Когда | Что делает бэк |
|---|---|---|
| `ocr_unavailable` | движок OCR недоступен | файл — статус `ocr` («нужен OCR»), разбор продолжается; повтор — `POST /runs/{id}/restart {files}` |
| `ocr_failed` | не удалось распознать | статус `error` с причиной |
| `ocr_partial` | часть страниц не распознана | `done` + предупреждение; значения с этих страниц — `present_not_extractable` только если видно, что значение есть |

Производительность: OCR страницы — 2–6 с на CPU; статья-скан на 20 страниц — до 2 мин. ML-2 обрабатывает страницы параллельно; таймаут `/ml/parse` для сканов увеличен до 600 с.
