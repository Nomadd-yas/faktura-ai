## 1. Что изменилось в спеке (кратко)

1. **Две области.** Область 2 (rag) больше не задел. У неё свои 7 CSV (`publications, configurations, datasets, tasks, experiments, results, issues`, колонки из `schema.json` `rag-viniti-adaptation-1.0`, в results 30 колонок), свой `check_submission.py` с кодами 0/1/2 и ключом `--ocr` (spec/14 §14.B).
2. **Статья — пара (`domain`, `publication_id`).** Коды D001… совпадают в двух областях.
3. **OCR обязателен для rag** (около 15 % PDF — сканы). OCR выполняет ML-2 в `/ml/parse`. Бэк определяет «нет текстового слоя», ставит `quote_found`, ведёт статусы и запускает проверку с `--ocr` (spec/11).
4. **Интерфейс работает с разборами Run (§15), а не с корпусами (§13).** Внутри бэка разбор — корпус с одним прогоном. API корпусов, `/facts/*`, resolve/reopen замечаний и старый `/papers/{id}` для фронта заменены.
5. **Форма данных для фронта — строки 7 таблиц шаблона** (значения строками, как в CSV). `review` и `meta` лежат отдельными полями.
6. **Правки и отметки замечаний привязаны к разбору.** Состояния замечаний `open|fixed|ok` с автозакрытием. Повторы наследуют правку основной записи. Есть сброс правок и журнал с `prev`. Правки влияют на выгрузку.
7. **Правило «лучшее значение»** — одно для сравнения, ответов и сводки (§15.13).
8. **Объём rag:** до 28 649 строк на статью, keyset-пагинация, `results=summary`, `GET /results/summary`.
9. **Нормализация rag (§6.6)** устроена иначе, чем solar: проценты и доли не пересчитываются по имени метрики.
10. **Проверки rag (§5.2-B):** `metric_scale`, `metric_k`, `normalization`, `protocol_mismatch`, `contradiction`. `check_name` — открытый текст.
11. **[В ФОНЕ]:** старый чат, проекты, граф по литературе, вопросы к коллекции. Вопросы внутри разбора (§15.9) и сеть связей (§15.10) нужны, но по Коорд. п.4 у них низший приоритет.
